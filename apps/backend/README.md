### Environment Files

- `.env.example` - Template with all required variables.
- `.env` - The file that contains the environment variables values that will be loaded into the application.
- `.env.test` - Test environment configuration. This is the only dot env file loaded when running tests.

To see which variables and values are expected at `.env` file or injected into the shell that the app will run and the meaning of each one, see [`environment.configuration.ts`](./src/shared/infrastructure/environment.configuration.ts).

## Local Development

### Database Migrations

We will use PostgreSQL v18

This project uses [DBMate](https://github.com/amacneil/dbmate) to handle database migrations located at [`./db/migrations`](`./db/migrations`).

It will read the `.env` to look up for the `DATABASE_URL` value to be used to manage the migrations executions.

It relies on the table `schema_migrations` (created automatically) to track the migrations.

To manage database lifecycle, use the following commands

```bash
# Run pending migrations
pnpm migrate

# Check migration status
pnpm migrate:status

# Create new migration
pnpm migrate:new migration_name
```

#### Run E2E tests

1. Create a `.env.test` file with the database credentials with the env vars starting with `DB_` to use for the E2E tests, according to the env. variables used in the `docker-compose.test.yml` file;
2. Ensure you have a fresh database to use on tests like;

```bash
docker compose -f docker-compose.test.yml --env-file .env.test up -d
```

3. Run `pnpm test-db-migrations:up`
   - just once to ensure that the DB is in a valid state
4. Run `pnpm test-db-seed:up`
   - just once after running the migrations as we want to fulfill the DB with the minimal data required for the test suites
5. Run the tests via `pnpm e2e/test`

#### Generating Code Coverage

In order to generate a code coverage report that covers all the kind of tests even if they are not running together, run these commands:

```bash
# Run the unit tests
pnpm unit/test --coverage --reporter=blob --outputFile=./.vitest-reports/unit.blob
# Run the integration test
pnpm integration/test --coverage --reporter=blob --outputFile=./.vitest-reports/integration.blob
# Run the E2E tests
pnpm e2e/test --coverage --reporter=blob --outputFile=./.vitest-reports/e2e.blob

## For the following, no tests will be run; just a code coverage report combining all the ones available in the `.vitest-reports` folder
pnpm coverage
```

The folder `coverage` will be generated after this.

### Quick Start

1. Clone the repository and navigate to the project directory
2. Copy the environment configuration:

   ```bash
   cp .env.example .env
   ```

3. Start the services with Docker Compose:

   ```bash
   docker compose --env-file .env up -d
   # To connect directly to the database services
   docker compose exec postgres psql -U nestjstemplatev2 -d nestjstemplatev2
   ```

4. Ensure that the database state is up-to-date:

   ```bash
   pnpm migrate
   ```

5. Verify the application is running:

   ```bash
   curl http://localhost:3000/v1/health
   ```
